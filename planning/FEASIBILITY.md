# 可行性记录 · 2026-10-28

以下区分已经验证的事实和后续仍需验证的判断。原始资料与完整试验输出只保存在本机。

## 学校页面

在已登录的 Edge 中读取了一节操作系统回放，打开其 PPT 栏后，页面 DOM 提供带时间的截图条目。样本中取得 79 条图片记录；首批时间包含 `00:00:01`、`00:02:54` 和 `00:11:22`。

实际下载并查看了一张 1280×720 图片，内容为教师电脑上的 PowerPoint 界面，显示“课后作业讲评”。因此“获取带时间的授课屏幕”有实证。访问位置是同一学校域名下的 `/play/ai3/ppt/…jpg`，无需复制学校 Cookie。

这不证明所有课都有此类资源，也不证明教室摄像头里的手写板书可读。本轮仅实现索引采集；OCR、公式、跨截图去重、原图权限过期与课程字幕对齐仍需继续验证。

## 本地资料

在学生提供的学期目录中，试验选择了三门课程的五份 PDF：项目要求、操作系统作业、操作系统导论、进程与线程课件、神经科学第一周课件。共提取 148 个带页码的片段。

中文问题“项目截止要求”“进程线程”“神经元”分别能检索到对应课程的材料，未混入其他课程。文件按内容指纹去重；新版本的原文与旧引文保留关系。

项目要求原文明确写了 `DDL：TBD`。真实 DeepSeek 调用能够列出交付要求并保留截止日期未知，没有把某个日期当成已确认期限。神经科学练习的实际调用也已成功，答案引用对应课件页。生成正确与学生学会是两个不同指标，不能由这两次试验推出长期学习效果。

首次练习试验发现 PDF 换行会造成引文匹配失败。实现已改为仅容忍空格与换行的排版差异，再保存真实原文片段；增加了拒绝改词和改否定关系的回归用例。

## 课表

使用学生的学校导出 PDF 试验，按九列表格读取到 22 条“课程—星期—节次—周次”候选规则，未将学生姓名、学号作为排程数据。

试验发现跨行的“学分”字段可能让下一门课沿用上一门课名，已修复并加入合成回归。原课表中存在不同课程时间重叠，不能替学生自行判断应该上哪门课。系统保留候选结果，需要核对开学日期和作息，展开后提示冲突。

## 技术基础

- 自定义分析循环，最多三次模型调用；来源和课程范围受代码约束。
- 模型提案不能自行成为任务、日历或通知。
- 已实现四个只读 stdio MCP 工具并进行协议测试，可作为平台接入基础；尚未完成 WorkBuddy 账号联调。
- 排程、日历导出、缺失日期、双来源纠错、无效引文、路径越界、旧来源、课表换行及 MCP 工具边界均有回归测试。
- 新功能使用独立数据库与接口，录音、转写和原有手机提醒不迁移。

## 当前限制与验证优先级

1. 检索目前采用课程范围、词项和少量中英术语映射，适合原型；复杂跨章节问题需要检索质量评测后再决定是否引入本地向量检索。
2. 引文的存在不等同于结论成立。下一步应以人工标注样本检查语义支持、教师修正和考试范围判断。
3. 复杂公式、扫描课件和手写板书不应直接进入可信知识库，需要视觉识别质量与人工回查路径。
4. 排程目前使用学生确认的耗时和每日时段；长期难度评估、知识依赖、自动补课路径和自适应耗时尚未实现。
5. 现有手机通道可以承接后续学习计划提醒，但本轮没有接入新的计划推送，也没有验证微信/QQ 接口。
6. 参赛材料必须同时展示可运行工作空间、真实平台链接及测试结果；本地可运行原型不等于已满足全部参赛条件。
