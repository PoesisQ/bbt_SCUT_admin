# 在 WorkBuddy 中用 SCUT 学习助手

用一句话查课堂出处、安排复习，或拿公开教材和论文对照课堂说法。课程索引留在本机，WorkBuddy 按需读取相关片段，并用自己的模型回答；这一层不再套一遍 DeepSeek。

## 本机接入

先在学习助手里导入至少一门课的字幕或资料，再在项目目录运行一次：

```powershell
.\.venv\Scripts\python.exe scripts\prepare_workbuddy.py --install
```

安装版将 Python 换为 `runtime\python.exe`。自定义资料目录时加 `--data-dir "实际资料目录"`。

脚本把 `scut-study` 合并到 `%USERPROFILE%\.workbuddy\mcp.json`，把技能放到同目录的 `skills/scut-study/SKILL.md`。已有连接器保留，改动前先备份；遇到同名的其他程序会停下，不覆盖。生成文件含本机路径，保存在数据目录的 `workbuddy/`，不要提交 GitHub。

在 WorkBuddy 的“专家·技能·连接器 → 连接器 → 自定义”检查 `scut-study`。客户端尚未加载时，用“添加 MCP”的 JSON 编辑器检查并保存生成的配置。如果出现信任或权限提示，请自己核对后操作。文件已写入不代表客户端已连接，最终应看到 **10 个工具**，且实际调用成功。

新建对话后可以这样说：

> 使用 SCUT 学习助手，检查连接。

> 操作系统老师在哪讲过条件变量？给我原句和回看位置。

> 今晚只有30分钟，先学什么？

> 查公开教材，核对条件变量为什么需要在 while 循环里等待；把课堂说法和教材的适用条件讲清楚。

WorkBuddy 负责启动 MCP 进程。查已有资料时不需要先开学习网页，也不需要重新登录百步梯。新录音和新字幕仍由学习助手导入、同步；回看学校视频时需要在浏览器登录。

## 哪个工具负责什么

| 工具 | 用途 |
| --- | --- |
| `study_connection_status` | 检查资料索引、版本与课程数量 |
| `list_study_courses` | 找到已有课程的名称 |
| `find_classroom_mentions` | 跨课时找原句、课时、时间与回放地址 |
| `search_course_sources` | 搜索本课字幕、教材、题目与外部参考 |
| `read_study_evidence` | 展开一段原文，检查版本和是否停用 |
| `list_confirmed_study_tasks` | 读取已确认且未完成的任务 |
| `plan_today_review` | 在 1–240 分钟预算内排序任务与复习 |
| `search_public_references` | 用公开概念词查论文和教材候选 |
| `read_public_reference` | 读取候选正文或摘要，按问题返回最多三段原文和页码 |
| `prepare_evidence_comparison` | 整理 2–6 段证据的出处、独立性和覆盖范围 |

公开检索会保存短期缓存，读取参考会增加未核验来源，其余工具不修改学习任务。没有通用命令执行、任意文件读取、录音控制、课程批处理或任务完成接口。这些操作继续在本机学习助手进行。调用记录可在学习助手的“运行详情”查看；其中不包含 WorkBuddy 模型内部的思考过程。

## 文献怎样参与核对

通用论文查 [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)，神经科学等生命科学主题查 [Europe PMC](https://dev.europepmc.org/RestfulWebService)。另有少量公开教材入口，例如 Wisconsin 的 [OSTEP](https://pages.cs.wisc.edu/~remzi/OSTEP/)。检索服务提供资料线索，本身不替我们判断结论正确。

检索只发送概念词，不把整段转写、文件路径或学生身份放进查询。缓存有效期为 24 小时，一次最多读两份候选；查不到正文时留下书目信息并说明缺口，不拿标题当证据。当前自动读取的论文内容主要是索引提供的摘要；教材读取也有页数和大小上限，不宣称通读整本书。

读取教材时传入文内检索词 `query`，工具就在本机从这份资料中选出最多三段完整片段。已经返回的原文直接用于对照，避免逐页取回再重复阅读。文内检索词不发给公开检索站。片段有页码和固定 ID；本次未匹配不等于整份资料没有讨论。

主 agent 先找课堂原话，再按同一个主张、同一组前提比较。回答区分“一致”“条件不同”“存在冲突”“证据不足”，给出原句、位置和来源。课程要求只能由课堂或老师提供的材料说明，外部论文不能推导考试范围。

出现实质分歧且宿主提供子 agent 时，最多增加一名复核者：只检查遗漏条件、摘要越界、引文支持度与重复来源。交接问题、争议点和至多六个证据 ID，不复制全部课程。普通查出处、排复习不启用团队；多名模型同意也不是事实证明。

同一 DOI 的转载、同一课时的学校字幕和本地转写不算独立证据。更正/撤稿提示会阻止该候选被直接当作支持材料，但这不是完整的撤稿核验服务。原始字幕不被改写，研究结果不会自动成为已确认知识。

## 资料库和动态记忆

课时位置、字幕版本、作答反馈与任务期限用 MCP 实时查。WorkBuddy 资料库适合放选定教材或可审阅产物，不能取代实时状态。需要静态快照时显式导出一门课：

```powershell
.\.venv\Scripts\python.exe scripts\prepare_workbuddy.py --export-course "操作系统"
```

输出 Markdown、`evidence.jsonl` 和 `manifest.json`，保留来源 ID、版本、页码或时间。不会自动上传；已有快照不会无提示覆盖。静态材料更新后，回答前仍需通过 MCP 检查当前版本。周期复习继续用学习助手的调度器，避免两边重复通知。

## 实际联调

2026-10-29，Windows、WorkBuddy 5.9.3：

已在客户端创建“SCUT 学习助手”工作空间，`scut-study` 显示在线、10/10 个工具启用。以下由 WorkBuddy 对话实际调用，调用记录可在本机运行详情查到：

| 验证 | 结果 |
| --- | --- |
| 连接检查 | 读取本机课程索引，返回可用工具数量 |
| 今晚 30 分钟复习 | 返回预算内安排；缺少期限与作答反馈时先做短诊断，不编造考试日期 |
| 跨课时查条件变量 | 返回真实字幕、课时、视频时间和回看链接；只有相关铺垫时说明缺少直接讲解证据 |
| 公开教材核对 | 完成公开检索、OSTEP 原文读取和证据对照；区分忙等与条件唤醒后的重检，保留页码与来源 |

这些 MCP 调用没有再次调用本地 DeepSeek，由 WorkBuddy 的模型组织回答。Crossref、Europe PMC 另有隔离数据库的联网检查。来源失效、同源重复、摘要范围、缓存、网络失败、配置合并、文内筛选及任务边界都有回归测试。

0.3.1 在客户端重新加载后复测通过：同一个条件变量问题，一次按问题读取就返回了所需教材片段，不再逐段发起七次读取。此结果说明工具往返减少，不代表所有问题都有固定的加速比例。

本机已接入后，打开 WorkBuddy，进入“SCUT 学习助手”工作空间即可继续提问。新对话需要时用 `/scut-study` 选择技能，也可以直接说“使用 SCUT 学习助手”。

当前没有发布公开 Agent 链接，`127.0.0.1` 不能作为评委可访问的链接。学校实际播放器的跳转定位仍需在登录环境验收。固定专家团和可视化工作流未部署；当前采用同一个 agent 按需取证，只有明确分歧才建议增加复核。

## 平台依据

采用官方 [MCP + Skill](https://open.workbuddy.cn/docs/connector) 接入方式，工具由本地 stdio 进程提供，不把课堂服务暴露到公网。技能格式见[官方说明](https://open.workbuddy.cn/docs/skill)。若之后部署固定角色团队，按[专家团规范](https://open.workbuddy.cn/docs/expert-team)配置，并以实际客户端工具权限为准。
