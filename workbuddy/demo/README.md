# 并发与时序演示

[原创讲义](并发与时序演示课.md)可以直接导入 WorkBuddy 个人资料库。配套的 [固定语料](corpus.json) 包含模拟课时、课件片段、不同计时的转写和更新过的版本。

第一批补学内容见[并发等待与唤醒](并发等待与唤醒.md)和[松针-27 时序补学](松针-27/时序补学.md)。[并发控制课程通知](并发控制课程通知.md)与[数字电路课程通知](数字电路课程通知.md)提供原创模拟的考试安排。网页示例库按课程读取通知，松针-27 的作业期限引用[教师改期通知](松针-27/教师改期通知.md)。

## 松针-27 专家团演示

使用[原创讲义第 7 页](并发与时序演示课.md#数字电路--第-7-页)、[原始实验通知](松针-27/原始实验通知.md)和[教师改期通知](松针-27/教师改期通知.md)。另备[同学转述](松针-27/同学转述.md)作对照。原始通知为 11 月 16 日 22:00 截止，教师改为 11 月 15 日 20:00。下列文字演示假设当前为 11 月 15 日 18:00，日期、发布者和课件均为原创样例。

1. 「我想补到能开始松针-27 实验。先用讲义第 7 页考我一道建立时间的题，等我作答。」沿前稳定时长由 `8 ns − 7 ns` 得到，要求是 `2 ns`。
2. 回答「满足要求，因为数据在有效时钟沿之前已经稳定。」接着说「请按我的原答定位错因，再给一道变式。」检查讲师引用原答并指出缺少的是时长比较。出题员只改一个条件，例如让数据改在 `6 ns` 稳定。学生仍需自己算出 `8 ns − 6 ns = 2 ns`。
3. 「我已核实这是演示课程中授课教师的原始通知。请核对松针-27 的新旧期限，先预览变更。报告还需 20 分钟，今天 19:00–19:30 可用，19:20–19:30 的预习已锁定。」预期规划师说明报告可从次日移到当日 19:00–19:20，并保留预习时段。使用资料库附件时可预览草案。使用隔离 MCP 演示数据时，确认后才能写回。
4. 新开任务说「接着刚才的松针-27 实验，告诉我之前怎么答的，报告现在什么时候交。」连接器路径应找回原答、已登记的变式和最新确认期限。只提供[同学转述](松针-27/同学转述.md)时，预期提示需教师原文并保留原期限。

用新目标重跑第 1、2 步，改答「8 − 7 = 1 ns，这是保持时间，建立时间要看时钟沿之后」。预期讲师指出学生对调了沿前和沿后的条件，变式要分别辨认建立时间和保持时间。另用「只讲解，请把这道题完整讲完」核对是否按学生意愿讲解。不同卡点触发不同复测，以上是客户端实测的判定标准。

### 准备隔离的 MCP 演示数据

在仓库根目录运行下列命令。第一条通过真实 stdio 执行完整回放；第二条仅生成未执行的演示索引、任务与计划。日期按运行当天推算，使用输出 JSON 里的期限、时段和证据 ID 替换上文固定值。

```powershell
.\.venv\Scripts\python.exe scripts\demo_workbuddy_team.py
.\.venv\Scripts\python.exe scripts\demo_workbuddy_team.py --prepare "$env:TEMP\scut-team-demo"
```

`--prepare` 传入一个未使用的空目录。客户端联调时，将隔离连接器的 `--data-dir` 指向该目录。协议回放检查写入、重试和续接，客户端验收另外查看实际成员回传与资料库保存结果。

## 重跑检索评测

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_workbuddy.py
```

脚本用临时索引启动真实的 MCP 进程。它检查中英术语、错课和空结果、原句与页码、视频及录音时间、同源矛盾、题位不足和布尔反例。然后重启进程，读取同一题、提交一次测试作答并重试，检查今日清单是否引用原来的题。结果写入 `dist/workbuddy-eval.json`，各问题的候选、延迟和返回大小均可查阅。要保留演示索引，使用 `--keep-data` 指向一个空目录。

## 在 WorkBuddy 验收

1. 在个人资料库选择“新建 → 上传和导入 → 上传文件”，上传原创讲义。新建任务，在输入框的“＋ → 添加文件 → 资料库”中附上它。
2. 请 WorkBuddy 说出讲义里的实验标签、计算建立时间缺口，并用两条原句解释唤醒后队列仍为空时怎么办。应读出「松针-27」，第 7 页的沿前稳定时间和缺口都是 1 ns，第 3、4 页支持在锁内循环重检谓词。
3. 请它生成一份带出处的 Markdown 复核稿，打开生成的文件，从产物工具栏保存到“我的资料”，再从资料库打开核对。只用本讲义和生成的演示稿。
4. 用 [专家团配置](../expert-team/README.md) 发起整套题单任务，核对主理人是否收到了出题和证据复核成员的回传。再用「只核对这两处说法是否冲突」验证仅调用复核员。用简单的单题请求验证当前对话直接完成。

如需在客户端检验第 4 步的本地检索，将保留的演示索引显式接到隔离的连接器配置。以客户端任务中的工具记录、成员回传和资料库中的产物为准。[本轮验证](../VALIDATION.md)记录了实际执行到的步骤。
